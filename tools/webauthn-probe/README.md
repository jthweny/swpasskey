# WebAuthn probe

Local test harness for the compatibility fork. It asks for exactly the
credential Daybreak asks for — cross-platform attachment, discoverable,
user verification required, `attestation: "direct"` — and decodes the
attestation object a security key returns.

```
python3 tools/webauthn-probe/server.py                 # http://localhost:8080
python3 tools/webauthn-probe/server.py --port 9000
python3 tools/webauthn-probe/server.py --tls           # self-signed HTTPS in ./certs
python3 tools/webauthn-probe/server.py --bind 0.0.0.0  # reach it from another device
```

Requires Python 3.9+ and `openssl` on `PATH` (certificate subject/issuer, and the
`--tls` certificate). Nothing else.

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | The probe page. |
| `GET` | `/options/register` | Registration options (`cross-platform`, `residentKey: required`, `userVerification: required`, `attestation: direct`, ES256+P-256 allowed). |
| `GET` | `/options/login` | Discoverable-credential assertion options (`userVerification: required`, empty `allowCredentials`). |
| `POST` | `/register` | Decodes and records a `navigator.credentials.create()` result. |
| `POST` | `/login` | Decodes and records a `navigator.credentials.get()` result. |
| `GET` | `/log` | The `registrations.jsonl` collected so far. |

`localhost` is a secure context in Chrome, so plain HTTP is enough for WebAuthn;
`--tls` exists for testing an RP that requires HTTPS or for a non-localhost
`--bind`.

## What it reports

* `fmt` and whether `x5c` is present, plus a per-certificate summary:
  subject, issuer, SHA-256 fingerprint, the AAGUID extension, and whether the
  leaf is self-signed.
* `authData`: AAGUID, credential id, COSE public key, raw flags, and the decoded
  flag names — UP, UV, BE, BS, AT, ED.
* `clientDataJSON`: type, challenge, origin.
* `signCount` on both registration and assertion, to show the counter moving.
* `credProps.rk`, `getTransports()`, and the reported authenticator attachment.

`attestation_kind` is one of:

| value | meaning |
| --- | --- |
| `self (credential key, no chain)` | packed self-attestation, no `x5c` — upstream behaviour, what synced/software passkeys typically produce |
| `x5c present, self-signed leaf` | this fork's default: a profile-named certificate that does not chain to a vendor root |
| `x5c present, vendor-style chain` | leaf + intermediates, e.g. `SWPASSKEY_ATTEST_CHAIN` |

## Reading a result

`BE` clear and `BS` clear means the credential is device-bound; a set `BE` bit
would mean it claims to be backup-eligible (a synced passkey). `UV` set means the
request's `userVerification: "required"` was actually honoured. The AAGUID in
`authData` is what a relying party maps through the FIDO MDS; the certificate
subject and fingerprint are what a chain-validating RP looks at.

`registrations.jsonl` keeps one JSON object per registration or assertion, so a
backend verdict can be tied to the exact bytes it received.

Certificates generated by `--tls` land in `./certs` and are git-ignored.
