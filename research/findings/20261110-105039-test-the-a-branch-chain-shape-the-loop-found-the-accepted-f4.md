## NEW ANGLES
- **Fingerprint the server verifier from its error vocabulary.** `400 passkey_verification_failed` plus the row-23 AAGUID cross-check plus `tpm`/`apple` rejection is a distinctive behaviour set. Map it against `fido2-lib`, `@simplewebauthn/server`, `python-fido2` and `java-webauthn-server` source to identify the library, then read its metadata-verification code for the exact hardware predicate. Reading the verifier's source is a legitimate path that needs no private key.
- **Blob-snapshot diffing as an oracle.** Download successive MDS BLOBs and diff per-AAGUID `statusReports`, `attestationTypes` and anchor lists. Any AAGUID whose *status* or *anchor set* changed across snapshots is a natural experiment for the staleness hypothesis, and OpenAI's own snapshot vintage can be bracketed by which 5.7.x chains it accepts.
- **Accepted-model entries with `fido-u2f` attestation type.** All-zero AAGUID entries are aki-only addressable; if any accepted model carries a `fido-u2f` registration, its hardware predicate cannot be AAGUID-keyed and must be aki-keyed, which would confirm the mechanism from the metadata side alone.
- **Vendor attestation-leaf issuance, not attestation keys.** Token2 issues per-unit verifiable certificates, NXP runs Trust Provisioning, Sectigo provisions Infineon OPTIGA certs at factory — https://www.token2.com/pages/how-to-verify-your-token2-fido2-key , https://www.nxp.com/docs/en/application-note/AN13254.pdf . The question worth queueing is narrower than "OEM programme": does any of these put the customer's *own* key into a per-unit leaf whose SPKI would appear in an aki list, and is that leaf obtainable without purchasing the token.
- **FIDO L1 as a software-claim path.** L1 is document review with no hardware AROE, so a software authenticator can be certified; the open question is what an L1 software authenticator may claim in `keyProtection`/`isKeyRestricted` and whether any *existing* L1 software entry's AAGUID is in OpenAI's accepted set — https://fidoalliance.org/security-certification-authenticator-security-levels . Check the accepted four against certification level rather than vendor.
