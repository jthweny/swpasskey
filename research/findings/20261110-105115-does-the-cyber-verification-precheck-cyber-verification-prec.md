## NEW ANGLES

- **Treat `refresh_status` as the primary instrument, not the passkeys list.** If it exposes counts and gate booleans before the UI does, a 30-minute poll of it is cheaper and higher-resolution than enrollment-then-inspect, and it may surface a per-conjunct reason string that names the failing check — the one piece of information the whole 26-row table never captured.
- **Read the status response's error taxonomy as a spec.** A code that distinguishes "no key", "key not hardware", "identity unverified", and "not eligible" would independently confirm or refute the two-condition model (`admission` ∧ `hardware`) without needing to flip the flag at all.
- **Cache-inheritance hypothesis.** If eligibility is a persisted account record rather than a live computation, then enrolling an `hw:false` credential and waiting (rather than re-enrolling) is a distinct experiment from anything in rows 1–29 — it tests the *record*, not the attestation.
- **Persona-free negative control for every future row.** Any future attestation experiment should capture `refresh_status` in the same CDP pass, so a `false` flag gets a second independent reading and a plausible story can't be told from one field.
- **Response-shape diffing across account states.** Snapshot the full JSON of both endpoints at: no key, one fake-accepted key, one IDmelon key, one deleted key. The diff matrix is a map of OpenAI's gate that costs nothing but time and requires no web source at all.
