- OpenAI Support has stated that "keys supplied through the OpenAI/Yubico bundle are supported for Daybreak" — the qualifying set is named as the bundle, in writing — https://community.openai.com/t/daybreak-does-not-recognize-trustkey-t110-physical-fido2-keys-as-hardware-security-keys/1401917

Genuine-chain alone does not produce the flag — https://community.openai.com/t/daybreak-does-not-recognize-trustkey-t110-physical-fido2-keys-as-hardware-security-keys/1401917 / https://community.openai.com/t/daybreak-trustkey-t110-t120-confirmed-ineligible-compatibility-requirements-were-clarified-too-late/1402777

- Signal 2 (`tac1_enabled`) is provably not credential-only: Daybreak requires eligible paid plan + Advanced Account Security + ≥1 qualifying physical key + identity verification (Persona) + review, and "fixing the security-key setup does not automatically restore Daybreak access" — any flag-only win is a partial finding — https://help.openai.com/en/articles/20001258-openai-daybreak-trusted-access-for-cyber-overview / https://help.openai.com/en/articles/20001259-troubleshooting-openai-daybreak
- MDS structure: exactly three AAGUID entries carry zero attestation roots, all `basic_surrogate` — Windows Hello Software Authenticator, TruU, Sherlocked; 333 entries total (261 certified, 72 `NOT_FIDO_CERTIFIED`, 1 ever `REVOKED`) — https://github.com/sebadob/rauthy/issues/1618
- Spec-sanctioned anchorless class: surrogate basic attestation ⇒ `attestationRootCertificates` MUST be empty and no trust anchor is used at all — https://fidoalliance.org/specs/mds/fido-metadata-statement-v3.0-ps-20210518.html / https://fidoalliance.org/mds-portal-user-guide-for-vendor-users
- MDS listing does **not** require FIDO certification ("FIDO Certification is an optional service and is not required for listing your metadata statement"); Associate membership is $3,250 (≤100 employees); L1 functional cert $6,000 member/$9,000 non-member with L1 security included — https://fidoalliance.org/mds-portal-user-guide-for-vendor-users / https://fidoalliance.org/members/become-a-member / https://fidoalliance.org/fido-certification-fees
- Software authenticators are explicitly certifiable (L1+ exists for software: white-box crypto instead of an AROE), so a software authenticator can be an MDS vendor of record — https://fidoalliance.org/certification/authenticator-certification-levels/authenticator-level-1-2 / https://fidoalliance.org/fido-user-authentication-certification-programs
- Vendor-shipped known attestation material exists: SoloKeys `bundle-secure-non-solokeys.hex` ships a published "default" attestation key ("no security concern with using our default attestation key"); Solo 1 firmware repo carries default attestation cert/key in-tree; Solo 2 Hacker ships with none — https://docs.solokeys.io/programming / https://solokeys.com/pages/solo-2-guide / https://github.com/solokeys/solo1
- Spec confirms shared model-wide attestation keys ("Full Basic Attestation") and re-issuance of certs for recorded attestation keys after CA compromise — i.e. anchors and leaves are model-scoped, and a leaf we can hold exists wherever a vendor published one — https://fidoalliance.org/specs/fido-v2.0-ps-20150904/fido-key-attestation-v2.0-ps-20150904.html
- The standard RP design OpenAI likely mirrors is documented by Entra: "a complete certificate that chains back to the attestation roots extracted from the FIDO Alliance MDS", vendors responsible for publishing roots to MDS — https://learn.microsoft.com/en-us/entra/identity/authentication/concept-fido2-hardware-vendor
- "Non-exportable" has a protocol-level meaning independent of attestation: WebAuthn L3 BE/BS flags (BE=0 ⇒ device-bound) — our rows all presented BE=0 (`flags=0x45`) and still got false, so the flag is not BE-derived — https://fidoalliance.org/webauthn-level-3-is-now-a-w3c-recommendation
- Yubico's own RP guidance concedes non-attestable AAGUIDs (no roots) can't be attested and recommends "compensating controls" — leaving room for verifier fail-open/fail-closed variance in exactly the anchorless class rows 13–14 hit with `packed` — https://docs.yubico.com/hardware/yubikey-guidance/best-practices/rp-bestpractices-mds.html
- Forrester (analyst, quoting OpenAI): "OpenAI also supports other FIDO-compatible hardware keys" for AAS — public claim that the qualifying set is wider than the bundle, in tension with the TrustKey verdicts — https://www.forrester.com/blogs/openai-makes-hardware-passkeys-mandatory-for-its-highest-end-cyber-model

## EXPERIMENTS
1. **Fresh-account control (this iteration's angle)**: new account, real YubiKey 5C NFC fw 5.8, real browser ceremony; before enroling, capture the attestation `x5c` + AAGUID (daemon-side tap or `ykman`, keep the cert chain); after enroling, poll signal 1 (`GET /api/accounts/advanced-account-security/passkeys`) and signal 2 at t+2/10/30 and t+24h, and record `authenticator_name` verbatim | expect: `true` at t+2 = flag computed synchronously from attestation (crypto/allowlist); `false→true` by t+30/t+24h = async pipeline, all prior rows need re-polling; `false` forever on genuine 5C NFC = the flag is operator-set (bundle-SKU-only) and no amount of attestation shaping will ever flip it | proves: whether signal 1 is cryptographic or operator-set, plus the ground-truth latency baseline every future row is judged against
2. **AAGUID fingerprint of the real key vs claimed AAGUIDs**: compare the captured attestation AAGUID of the real key (and, when on hand, the "YubiKey C NFC – OpenAI" bundle key) against `f4ce5fc0`/`d7781e5d`/`a25342c0`/`2fc0579f` and the name echo ("…(Consumer Profile)") | expect: bundle key reports a *distinct* AAGUID/profile name not in our claimed set | proves: the hardware list is keyed to OpenAI-profile MDS entries we have never claimed — a new target for the daemon
3. **Anchor-as-leaf chain collapse** (new; rows 1–9 all used our own leaf): admitted AAGUID `f4ce5fc0`, `fmt:"packed"`, `x5c` = [genuine Yubico Attestation Root 1] alone (self-signed CA == its own trust anchor ⇒ zero-length path builds trivially), `attStmt.sig` = arbitrary bytes (row 3 shows it is not checked) | expect: 200 + `is_non_exportable_hardware_key: true` if "chains to the model's anchor" is the whole chain half of the flag; 200 + `false` if a leaf-signed-by-anchor signature at X.509 level is also required | proves: the chain half of the model is directly reachable with publicly known material — the single highest-value untested construction
4. **`fmt:"none"` sweep over the refused classes** (row 12 tested `none` only on an admitted AAGUID): TruU `bb878d7b`, Allthenticator `5ca1ab1e`, IDmelon `39a5647e`, and the three anchorless `basic_surrogate` AAGUIDs (pull from local MDS BLOB), empty attStmt | expect: 400 ⇒ the model gate is AAGUID-keyed regardless of format; 200 + `true` on any anchorless entry ⇒ verifier fails open when no anchor exists and sets the flag | proves: whether the admission gate is format-conditional and whether the anchorless class reaches signal 1 (angle 1's exact question)
5. **`fido-u2f` format on an admitted AAGUID**: build the U2F attStmt (sig over the fixed U2F base, `x5c` = self-made) and a variant with `x5c` = [Yubico root] | expect: 400 confirms "only packed is admitted" as a gate rule; 200 (esp. with anchor `x5c`) shows a second, laxer verifier path | proves: whether the packed-only finding is policy or an artifact of one code path
6. **Post-enrolment flag mutation probe**: on the existing account, take one flagged-`false` credential through a full assertion (sign-in), then re-query signal 1 at t+2/10 | expect: `false` (flag is enrolment-time immutable) — but if `true`, the "delayed backend state update" reports are assertion-triggered | proves: whether late classification is time-based or usage-triggered
7. **Signal 2 dependency probe** (if experiment 1 yields a flagged-`true` key): query `POST /backend-api/cyber_verification/status` at AAS-complete-but-pre-IDV and post-IDV states | expect: `tac1_enabled` stays `false` until plan + AAS + IDV + review are all satisfied | proves: signal 2 is not credential-derived — confirms partial-finding labelling is mandatory for every flag-only win
